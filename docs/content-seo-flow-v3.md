## フェーズ1: キーワード選定

**インプット:** 競合キーワードCSV（SEMrush形式）、フェーズ9の分析結果

**ルール:**
1. **検索意図の確認を必ず最初に行う**（トリマー事件の再発防止。複合KWは実効ボリュームを推定する）
2. 判断基準: 即攻め＝KD≤30×Vol≥1,000 / 狙い目＝KD≤30×Vol≥300 / ロングテール＝KD≤35×Vol≥100
3. 検索意図を3分類してから記事タイプを決める
   - 情報収集（〜とは・使い方）→ 工具解説記事
   - 比較検討（レンタルvs購入）→ 比較記事
   - 購買意図（レンタル・料金・どこで借りる）→ CV直結記事
4. フェーズ9の実績データ（表示回数・CTR・順位）があれば優先的に参照する

---

## フェーズ2: 一次情報リサーチ ★新規

ネットのキュレーション情報だけで書いた記事はもう上位表示されない。
E-E-A-Tの最初のE（Experience＝一次体験）を記事に注入する。

**みんなのレンタル工具における一次情報ソース:**

| ソース | 取得できる一次情報 | 使い方 |
|---|---|---|
| 自社の運営データ | レンタル人気ランキング・実際の貸出期間分布・破損事例 | 「当店の実績では〜」として記事に挿入 |
| 実際の梱包・発送オペレーション | Pelicanケース梱包・ゆうパック返送の実写真と手順 | 返却手順記事・FAQで独自写真を使用 |
| X検索 | 工具名で検索し、実ユーザーの失敗談・活用例を収集 | 「よくある失敗」セクションの実例ソースに |
| YouTube文字起こし | 工具レビュー動画の文字起こし→使用感・注意点を抽出 | 既存ワークフロー（YouTube transcript→Claude変換）を流用 |
| 自分で工具を使った記録 | 商品仕入れ時の開封・試用メモ・写真 | 商品ページ・記事のオリジナル画像/コメントに |

**実行ルール:**
- 記事1本につき最低1つの一次情報を入れる（当面の必須基準）
- X・YouTube由来の情報は「実際のユーザーからは〜という声がある」と出典の性質を明示
- 自社データが貯まるまでは「梱包・返送オペレーションの実写真」が最も再現性の高い一次情報

---

## フェーズ3: 競合分析

（従来通り・変更なし）
- 狙うKWで上位10記事を調査し、タイトル・H2・H3・カバートピックを抽出
- 共通パターン＝必須トピック、欠けている観点＝差別化ポイントとして整理
- **文章の模倣は禁止。** 構成パターンとトピックのみ参考にし、表現は完全オリジナルで書く

---

## フェーズ4: カニバリチェック

（確立済みフロー・変更なし）
```
① 同じ工具・テーマの記事が既にあるか？
② あれば検索意図が異なるか？（情報収集/比較検討/購買意図）
③ 意図が同じ → 既存記事に統合
   意図が異なる → 内部リンクでファネルを設計
```

---

## フェーズ5: 構成作成 → 執筆

**構成ルール:**
- H1にメインKWを含める
- リード文は読者の悩みへの共感→解決の約束（100〜150字）
- 「この記事でわかること」ボックスを冒頭に設置
- CTAは中間＋末尾の2箇所以上（文章の流れで自然な位置に）
- 比較・手順は表で整理

**E-E-A-T対応（★新規）:**
- 記事末尾に運営者情報ブロックを挿入する
  - 「この記事の執筆・監修: みんなのレンタル工具 運営チーム」
  - 運営者プロフィールページへのリンク
  - 実際にレンタル商品を仕入れ・検品・梱包している事業者である旨を明記
- WordPressテーマ側に著者ボックスを実装する（functions.php対応・別タスク）

## フェーズ6: 品質スコアリング ★新規

執筆完了後、以下の100点満点チェックリストで採点する。**95点未満は修正して再採点。**

| 項目 | 配点 | 判定基準 |
|---|---|---|
| 検索意図への適合 | 20 | タイトル・H1・リードがKWの意図に応えているか |
| 一次情報の有無 | 15 | 自社データ・実体験・X/YouTube由来の独自情報が1つ以上あるか |
| オリジナリティ | 15 | 上位記事にない切り口・表・数値があるか／表現の模倣がないか |
| 構成の網羅性 | 10 | 上位10記事の必須トピックをカバーしているか |
| CTA設計 | 10 | 中間＋末尾の2箇所以上・ユーザー行動と整合しているか |
| カニバリなし | 10 | 既存記事と検索意図が重複していないか／内部リンク設計済みか |
| メタ情報 | 10 | title（32字前後・KW含む）/ meta description（120字前後）/ slug |
| 事実の正確性 | 5 | 料金・仕様・他社情報が最新の調査に基づいているか |
| E-E-A-T要素 | 5 | 運営者情報・出典の明示があるか |

**採点はフロントマターに記録する:**
```yaml
quality_score: 96
scored_at: 2026-06-13
```

## フェーズ7: 人間レビュー（Human-in-the-loop）

AIが自動で進めて良い範囲と、人間（Shu）の確認が必須のポイントを明確化する。

| 工程 | AI自動 | 人間チェック |
|---|---|---|
| KW選定・リサーチ・執筆・採点 | ✅ | — |
| 記事の公開判断 | — | ✅ 必須（特に料金・規約・競合言及） |
| 価格・サービス条件の記載 | — | ✅ 必須（¥700〜・送料無料条件など実際の設定と一致するか） |
| 内部リンク・リライトの実行 | ✅ 提案まで | ✅ 実行承認 |

## フェーズ8: 入稿・公開・インデックス登録

1. Markdownからの入稿（WordPress REST API経由の自動入稿を構築予定・別タスク）
2. アイキャッチ画像の設定（HTML/CSS→スクリーンショットの既存ワークフロー）
3. 公開後、Google Search ConsoleでURL検査→インデックス登録をリクエスト
4. 公開URLを記事管理表（フェーズ9）に記録

## フェーズ9: 計測・分析 → フィードバック ★新規

**計測サイクル:** 公開2週間後に初回チェック、以降月次

**見る指標（Search Console / GA4）:**

| 指標 | 判断 | アクション |
|---|---|---|
| 表示回数が増えない（公開4週間後も僅少） | インデックス・KW選定の問題 | インデックス状況確認→KW再検討 |
| 表示は多いがCTRが低い（<2%） | タイトル・メタの問題 | title/descriptionをリライト |
| 順位11〜20位で停滞 | コンテンツの厚みの問題 | 一次情報・FAQ追記でリライト |
| 流入はあるがCV（レンタルページ遷移）しない | CTA・導線の問題 | CTA文言・位置を変更 |

**フィードバック:** 分析結果から「伸びているKWの周辺KW」を抽出し、フェーズ1の選定候補に追加する。

---

## フェーズ10: 週次メンテナンス ★新規

毎週1回、以下を実施する。

1. **内部リンク見直し:** 新規記事が増えたら関連既存記事から内部リンクを追加（例: 12ハンマードリル→20コアドリル）
2. **リライト候補の抽出:** フェーズ9の指標で「順位11〜20位」「CTR低」の記事をリストアップ
3. **情報の鮮度確認:** ホームセンター比較系記事（06・13・14）の料金・サービス内容は変動するため四半期ごとに再調査
4. **カニバリ再チェック:** 記事が増えるたびに意図の重複が発生していないか全体を見る

# 付録B: SKILL.md 定義（Claude Code自動化用）

Claude Codeでこのフローを自動実行させるためのスキル定義。
`/mnt/skills/user/seo-article/SKILL.md` 相当の内容としてリポジトリに保持し、記事生成タスク時に読み込む。

```markdown
# Skill: みんなのレンタル工具 SEO記事生成

## 目的
工具レンタルサービスのSEO記事を、一次情報を含み・カニバリを避け・95点以上の品質で生成する。

## 入力
- 狙うキーワード（または競合CSV）
- 商品ID（CTA先）

## 手順（厳守）
1. フェーズ1: 検索意図を必ず最初に確認。複合KWは実効ボリュームを推定する。
2. フェーズ2: 一次情報を最低1つ収集（自社データ／X検索／YouTube文字起こし／梱包・返送オペ写真）。
3. フェーズ3: 上位10記事のH2/H3を抽出。構成パターンのみ参考にし表現は完全オリジナルで書く（模倣禁止）。
4. フェーズ4: docs/articles/ 配下の既存記事と検索意図が重複しないか確認。重複なら統合または内部リンク設計。
5. フェーズ5: 構成→執筆。CTAは中間＋末尾。末尾に運営者情報ブロック。
6. フェーズ6: 100点満点で採点。95点未満は修正して再採点しフロントマターに記録。
7. フェーズ7: 公開判断・価格記載は人間（Shu）の承認を待つ。勝手に公開しない。
8. 出力: docx（Shu確認用）＋ Markdown（docs/articles/）の両方を生成しgitコミット。

## 厳守ルール
- 既存記事の文章・構成の模倣をしない（IP保護・カニバリ防止）
- 料金・規約・競合情報は最新のweb調査に基づく。古い記憶で書かない。
- 一次情報のない記事は完成とみなさない。
- トリマー事件の教訓: 複合KWのボリュームを額面通りに受け取らない。

## 出力形式
- docx: /mnt/user-data/outputs/article_xxx.docx
- md: docs/articles/NN_slug.md（連番）
- コミットメッセージ: "feat: 〇〇記事を追加（Vol/KD・差別化ポイント）"
```

# 付録D: v2からv3への移行で「やらないこと」

動画では完全自動化（人間ノータッチ）を推奨しているが、本サービスでは以下は自動化しない。理由を明記する。

| 項目 | 自動化しない理由 |
|---|---|
| 料金・送料条件の記載 | 実際のStripe設定・配送規約とズレるとクレーム・信用失墜に直結するため人間確認必須 |
| 競合他社への言及 | 事実誤認は法的リスク。最新調査と人間チェックを通す |
| 公開の最終判断 | 検索順位だけでなくブランド・正確性の観点で人間が5サインを出す（Human-in-the-loop） |
| 規約・法務に触れる記述 | 特商法・利用規約と整合が必要なため自動公開しない |

完全自動化の魅力はあるが、レンタル＝金銭・規約が絡む事業のため「品質チェックは人間」を堅持する。
