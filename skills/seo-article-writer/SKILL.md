# SEO記事制作スキル（汎用）

このスキルは特定の業種に依存しない。プロジェクト固有の情報（ドメイン・商品・CTA先・
競合・トーン）はすべて同ディレクトリの `project.config.md` に切り出してある。
**まず最初に `project.config.md` を読み込み**、そこで定義された設定を使って以下の手順を実行する。

---

## 起動時の最初の手順

1. 同ディレクトリの `project.config.md` を読む。なければユーザーに作成を促す（テンプレは末尾）。
2. リポジトリ内の既存記事ディレクトリ（config記載のパス）を一覧し、既存テーマを把握する。
3. 記事管理表（config記載のCSV）があれば読み、公開済み記事の実績を確認する。

---

## 制作フロー（10フェーズ）

### フェーズ1: キーワード選定
- **検索意図を必ず最初に確認する。** 複合KW（複数の意味を持つ語）は実効ボリュームを推定し、額面のVolを鵜呑みにしない。
- 判断基準: 即攻め=KD≤30×Vol≥1,000 / 狙い目=KD≤30×Vol≥300 / ロングテール=KD≤35×Vol≥100（configで上書き可）
- 検索意図を3分類し記事タイプを決める:
  - 情報収集（〜とは・使い方）→ 解説記事
  - 比較検討（AとB・どちらが得）→ 比較記事
  - 購買意図（料金・申込・どこで）→ CV直結記事

### フェーズ2: 一次情報リサーチ（configで必須/任意を設定）
- ネットのキュレーションだけで書かない。E-E-A-Tの最初のE（経験）を入れる。
- ソース例: 自社データ / X検索 / YouTube文字起こし / 自分で試した記録。
- configで `primary_source_required: false` の場合はこのフェーズを省略可。

### フェーズ3: 競合分析
- 狙うKWで上位10記事のtitle/H2/H3を抽出。
- **構成パターンとトピックのみ参考にし、表現は完全オリジナルで書く（模倣厳禁・IP保護）。**
- 共通項=必須トピック、欠落=差別化ポイントとして整理。

### フェーズ4: カニバリチェック（毎回必須）
```
① 同テーマ・同工具/同商材の記事が既にあるか？
② あれば検索意図が異なるか？（情報収集/比較検討/購買意図）
③ 意図が同じ → 既存記事に統合
   意図が異なる → 内部リンクでファネルを設計
```

### フェーズ5: 構成・執筆
- H1にメインKWを含める。リード文は悩みへの共感→解決の約束（100〜150字）。
- 冒頭に「この記事でわかること」ボックス。
- CTAは中間＋末尾の2箇所以上（自然な位置に）。configのCTA先URLを使う。
- 比較・手順は表で整理。
- configで `author_block: true` なら末尾に運営者情報ブロックを付ける。

### フェーズ6: 品質スコアリング（100点満点）
| 項目 | 配点 |
|---|---|
| 検索意図への適合 | 20 |
| 一次情報の有無 | 15（任意設定時は配点を再分配） |
| オリジナリティ | 15 |
| 構成の網羅性 | 10 |
| CTA設計 | 10 |
| カニバリなし | 10 |
| メタ情報（title/meta/slug） | 10 |
| 事実の正確性 | 5 |
| E-E-A-T要素 | 5 |
- 合格ライン= configの `quality_pass_line`（既定80）。未満は修正して再採点。
- 採点結果はフロントマターに `quality_score` / `scored_at` で記録。

### フェーズ7: 人間レビュー（Human-in-the-loop）
- 料金・規約・競合言及・公開判断は**人間の承認を待つ。勝手に公開しない。**
- それ以外（KW選定・リサーチ・執筆・採点）は自動で進めてよい。

### フェーズ8: 入稿・公開・インデックス登録（公開系はconfig/環境依存）
- Markdown→CMS入稿（手段はconfig記載）。公開後GSCでインデックス登録をリクエスト。
- 公開URLを記事管理表に記録。

### フェーズ9: 計測・分析→フィードバック（公開後）
- 公開2週後・以降月次で 表示回数/CTR/順位 を確認。
- 「順位11〜20位で停滞」→ リライト、「CTR<2%」→ title/meta改善、等のアクション。
- 伸びたKWの周辺KWをフェーズ1の候補に還元。

### フェーズ10: 週次メンテナンス
- 新記事追加のたびに内部リンクを更新。
- リライト候補抽出・情報の鮮度確認・カニバリ再チェック。

---

## 出力形式（configで上書き可）
- Markdown: `{articles_dir}/NN_slug.md`（連番・フロントマター付き）
- 必要なら docx を `outputs/` に併産。
- gitコミット: `feat: 〇〇記事を追加（Vol/KD・差別化ポイント）`
- pushはユーザー提供のPAT/承認が必要。pushの可否はconfigに従う。

## 普遍的な厳守ルール
- 既存記事の文章・構成を模倣しない（IP保護・カニバリ防止）。
- 料金・規約・競合・最新事情はweb調査ベース。古い記憶で書かない。
- 検索意図を疑う（複合KWのVolを額面で受け取らない）。
- 公開・価格・規約に関わる判断は人間の承認を必須とする。

## project.config.md テンプレート（新プロジェクトで作成）

```markdown
# プロジェクト設定: {サービス名}

domain: https://example.com
articles_dir: docs/articles
master_csv: docs/article-master.csv
cta_base: https://example.com/（CTA先のベースURL）
cta_pattern: /rental/?product_id={id} （CTAのURL形式）

# 競合・参照
competitors: [example-a.com, example-b.com]
keyword_source: 競合オーガニックKWのCSV（SEMrush形式）等

# 執筆設定
tone: 丁寧・初心者向け／専門的 など
accent_color: "E85A2B"（docx生成時のアクセント色）
font: Noto Sans JP

# 品質・運用ポリシー
quality_pass_line: 80
primary_source_required: false
author_block: false
auto_publish: false   # 公開は人間承認

# KW判断基準（既定を上書きする場合のみ）
kd_max: 35
vol_min: 100
```
